## Defaults and workflow
- Paste an authorized URL or choose an existing authorized local recording. Confirm acquisition/reuse permission.
- Smart quality, 60-second intervals, three target highlights, minimum score 85, Smart Replay on, full scan off, word-highlight captions, independent review on, alternates and extra overlays off. Click Generate ready-to-upload Shorts. The UI shows each accepted MP4 as it arrives; download and review it before uploading manually. Public YouTube/Instagram publishing remains separate opt-in and requires existing account/rights confirmations.
- Gaming Pro retains 1080×1344 gameplay and 1080×576 facecam. No periodic gameplay shake. For other content, choose Creator/Clean plus Automatic AI Style or a relevant preset. Single-face tracking and fit fallback are conservative; true active-speaker/subject/object detection is not implemented.
- Scores: hook 25%, retention 25%, entertainment 20%, story 15%, emotion/surprise 10%, rewatch 5%. Existing optimized quality penalties are deducted from the weighted base; misleading or duplicate candidates are rejected. A separate review can lower the score. Old sessions keep their historical scores. No prediction is a guarantee. Default duration preference 15–45s; optimized mode allows 10–90s for complete moments. Reject incomplete speech boundaries; retain contextual evidence and payoff.
- No new music, artificial effects, external audio, beat analysis, recommendation or music downloads during clipping. The renderer ignores stale external-audio environment variables and timeline metadata; old audio import/remix API requests are rejected, and old CLI import/generation flags fail. Legacy license inspection remains for existing V15 files and receipts. Previously generated MP4s are not changed or stripped of existing music. Re-generate them if original-only audio is required. Audio already embedded in the source remains; verify original rights before upload. No claim of automatic copyright clearance.
- Gaming masters already have compression and loudness normalization: subsequent caption render copies their encoded audio instead of filtering/re-encoding it again. General masters receive original-track highpass/compression/loudness normalization (−16 LUFS target, −1.5 dBTP starting target, not guaranteed platform requirements). Audio is not separated into speech/game stems. Output remains 1080×1920 H.264/AAC, 30fps, no app watermark.

## Visual reference
The supplied YouTube Short could not be inspected in this environment. Use an authorized local reference, 1–180 seconds, in Visual reference style > Analyze reference. The basic mode samples frames at 2 FPS for scene-change interval estimates and never processes reference audio. Optional existing Gemma visual model reviews stills and suggests a caption style when supported by evidence. Select its saved profile and optionally Match reference captions. Profile influences the selection prompt and the caption preset, not a replicated edit or audio/style transfer. No copied footage or branding. Profiles are stored in `~/.config/m4-shorts-studio/visual-references`. Old audio-based reference profiles should be analyzed again.

## Speed and correctness
- Existing V14 selective range acquisition, single preview prefetch worker, verified overlap/ASR reuse, bounded vision, cache and hardware encoder probing retained. No required full download for compatible replay formats. Live mode begins at available live edge and processes closed segments; unavailable formats, long waits for strong content, model inference, and network limitations remain.
- Authorized local recordings with Smart Replay and viral mode use bounded low-resolution previews instead of capturing the whole file. Fast/Smart use original-source direct rendering when multiple waveform anchors and visual alignment match, retaining verified source timestamps. Otherwise acquire a bounded candidate and re-transcribe as needed. No unsafe assumption that all previews match. Professional mode retains deeper review. Rendering still has per-shot intermediates and a caption-video encode when necessary.
- Near-identical rendered highlights are screened in the current session before publishing or exposing the MP4 (conservative five-frame hashes and similar durations). Timestamp/lexical duplicate and publishing ledger checks also remain. No perfect semantic duplicate detection.
- Pause/resume at safe replay boundaries and in-process HTTP retries retained. Full durable resume after crash/restart is not implemented. Existing completed clips remain in library.
- Technical validation checks format, decode, volume, black/silent/frozen frames and track timing; caption confidence and source-token overlap when available. Independent editorial review checks content before rendering. Not actual lip-sync, semantic subtitle accuracy, automatic rights clearance, or guaranteed professional story quality. No new arbitrary freeze frames, slow-motion, or object highlights; natural loops are assessed rather than forced.

A human reviewer must compare actual highlight quality; AI scores across V15/V16 use different weights. Full M4/YouTube access and quality comparisons require local authorized media and running AI models.
